5. _index/writing-handoff.json 계약

AI 원고실은 vault 안의 정확히 이 파일을 읽는다.

_index/writing-handoff.json

예시:

{
          "version": 1,
          "mode": "new-structure-to-writing",
          "structureNote": {
            "path": "3.Structure/투자전략-보고서.md",
            "title": "투자전략 보고서",
            "id": "S-001",
            "claim": "핵심 주장은 여기에 적는다"
          },
          "picked": [
            { "path": "2.Permanent/시장-사이클.md", "id": "P-001" },
            { "path": "2.Permanent/리스크-프리미엄.md", "id": "P-002" }
          ],
          "project": {
            "title": "투자전략 보고서 초안",
            "genre": "investment-strategy-memo",
            "wordGoal": 5000,
            "status": "planning"
          },
          "targetWritingFolder": "4.Writing"
        }

필수/검증 규칙:

  • structureNote.path는 필수다.
  • 모든 path는 vault-relative POSIX 경로여야 한다.
  • /Users/... 같은 절대 경로는 reject된다.
  • ../ parent traversal은 reject된다.
  • picked는 없을 수 있다.
  • project, targetWritingFolder도 선택 필드다.

생성되는 project.json.sourceNotes는 다음 순서다.

{
          "sourceNotes": [
            "3.Structure/투자전략-보고서.md",
            "2.Permanent/시장-사이클.md",
            "2.Permanent/리스크-프리미엄.md"
          ]
        }

첫 번째는 구조노트, 그 뒤는 picked 영구노트다. 중복은 순서를 보존하면서 제거한다.

7. 배포 절차

배포는 실제 Obsidian 런타임에 영향을 준다. 대표님이 “배포해”, “설치해”, “옵시디언에 반영해”라고 명시할 때만 실행한다.

대표님 vault에 AI 원고실만 배포:

cd /Users/dongchanyoon/Documents/Work/Projects/14.zettel-writer-connect

        OBSIDIAN_VAULT_PLUGINS_DIR="/Users/dongchanyoon/Library/CloudStorage/OneDrive-개인/지식창고/.obsidian/plugins" \
          pnpm deploy:ai-manuscript

두 플러그인 모두 배포:

OBSIDIAN_VAULT_PLUGINS_DIR="/Users/dongchanyoon/Library/CloudStorage/OneDrive-개인/지식창고/.obsidian/plugins" \
          pnpm deploy

배포 후 Obsidian에서 필요:

Cmd+P → Reload app without saving 또는 개발자용 다시 로드
        또는 설정 → 커뮤니티 플러그인 → 해당 플러그인 off/on

단순 reload만 요청받은 경우에는 build/deploy를 실행하지 않는다. 먼저 현재 설치·활성 상태를 읽고, 앱만 새로고침한다.

VAULT="/Users/dongchanyoon/Library/CloudStorage/OneDrive-개인/지식창고"

        # Obsidian 실행 여부
        pgrep -fl Obsidian || true

        # 플러그인 설치 경로와 symlink 확인
        python3 - <<'PY'
        from pathlib import Path
        vault=Path('/Users/dongchanyoon/Library/CloudStorage/OneDrive-개인/지식창고')
        for pid in ['ai-manuscript-studio','zettel-connect','obsidian42-brat']:
            p=vault/'.obsidian/plugins'/pid
            print(pid, 'exists=', p.exists(), 'is_symlink=', p.is_symlink(), 'path=', p)
            if p.is_symlink():
                print('  ->', p.resolve())
        PY

        # 플러그인 활성화 여부 확인
        python3 - <<'PY'
        from pathlib import Path
        import json
        p=Path('/Users/dongchanyoon/Library/CloudStorage/OneDrive-개인/지식창고/.obsidian/community-plugins.json')
        data=json.loads(p.read_text())
        for pid in ['ai-manuscript-studio','zettel-connect']:
            print(pid, pid in data)
        PY

가장 확실한 reload는 정상 종료 후 재실행이다. 강제 종료가 아니라 AppleScript quit를 사용한다.

BEFORE=$(pgrep -x Obsidian || true)
        printf 'before_pid=%s\n' "$BEFORE"

        osascript -e 'tell application "Obsidian" to quit' || true
        for i in $(seq 1 20); do
          if ! pgrep -x Obsidian >/dev/null 2>&1; then
            echo "quit_confirmed_after=${i}s"
            break
          fi
          sleep 1
        done

        open -a Obsidian
        for i in $(seq 1 20); do
          if pgrep -x Obsidian >/dev/null 2>&1; then
            echo "reopen_confirmed_after=${i}s"
            break
          fi
          sleep 1
        done

        AFTER=$(pgrep -x Obsidian || true)
        printf 'after_pid=%s\n' "$AFTER"

배포 후 확인:

ls -l "/Users/dongchanyoon/Library/CloudStorage/OneDrive-개인/지식창고/.obsidian/plugins/ai-manuscript-studio"

완료 주장 전에는 source bundle과 vault 설치 bundle의 main.js, manifest.json, styles.css 존재 및 SHA를 비교한다. reload만 수행한 경우에는 “deploy는 하지 않았다”고 명시한다.

10. 자주 나는 문제

표 근거
데이터 표
증상 판단 / 조치
_index/writing-handoff.json 없음 정상 no-op. handoff 생성 전 상태다.
vault-relative path 오류 handoff JSON 안에 절대경로 또는 ..가 들어갔다. vault-relative로 고친다.
command가 Obsidian에서 안 보임 deploy 후 Obsidian reload/off-on이 안 됐을 가능성.
AI CLI가 작동하지 않음 Codex/Claude CLI 경로와 로그인 상태를 확인한다. API key를 repo에 넣지 않는다.
source 수정했는데 UI가 그대로임 build/deploy/reload가 안 된 상태다. source 변경만으로 live plugin은 바뀌지 않는다.
styles.css를 고쳐도 되나 직접 고치지 않는다. source CSS를 고치고 build한다.
packages/zettel-connect를 고쳐도 되나 원칙적으로 금지. 13번 원본과의 동기화 계획이 있을 때만 한다.
