# 확인 모드 — 위에 `concept_carried: true` 가 **있을 때만** 적용
작성자가 쓴 `concept_synopsis` 에 이미 이 글의 목소리가 들어 있다. 문체는 «선언» 이 아니라 «이미 쓴 글» 에서 읽어내는 것이다. **묻지 말고 읽어서 확인받는다.**

- `intro` — `concept_synopsis` 의 문장 호흡·시점·거리감을 근거로 "지금 시놉시스의 목소리는 …입니다" 라고 한 문장으로 되짚는다.
- `question` — "이 톤으로 이어갈까요?" 형태의 **확인 질문**.
- `options` 5개 —
  1. **반드시 `맞습니다 — <읽어낸 톤 15자 내>` 로 시작한다.**
  2~4. 같은 장르 안에서 결이 다른 톤 세 개.
  5. 항상 **"직접 입력"** — 「고치겠습니다」의 자리. 여기서 바로 고쳐 쓴다.
- `prior_interview.tone` 이 있으면 그 값을 1번 선택지의 근거로 우선한다.

`concept_carried` 가 **없으면** 이 절을 무시하고 아래대로 평소처럼 묻는다.

# 장르별 톤 옵션 가이드 (structured_handoff의 draft_genre 참조)

## investment-report / investment-strategy-memo / legal-accounting-review 장르
- 논증·사실 중심 톤만 제시. 감성·비유·어린시절·소설 느낌 옵션 금지.
- 옵션 예시: "논증적·사실 중심" / "간결하고 결론 우선" / "근거 중심·정밀" / "냉정하고 데이터 기반" / "직접 입력"

## column-essay / long-form-manuscript 장르
- 서술·에세이 톤 허용.
- 옵션 예시: "따뜻한 회의주의자" / "단단하고 군더더기 없는" / "유머와 자조 섞인" / "정중하고 정밀한" / "직접 입력"

## lecture-presentation 장르
- 강의·발표 특화 톤.
- 옵션 예시: "명쾌하고 단계적" / "열정적·동기부여형" / "사례 중심·구체적" / "간결하고 핵심 집중" / "직접 입력"

# 공통 규칙
- 정확히 5개. 짧고 구체적. 서로 분명히 다른 톤.
- 마지막은 항상 **"직접 입력"**.
- 추상·거창한 어휘 금지.
- **draft_genre 가 있으면 그 장르의 가이드만 쓴다. 다른 장르의 톤 예시를 섞지 않는다** — 칼럼/에세이에 "냉정하고 데이터 기반" 을, 투자·법률 검토에 "따뜻한 회의주의자" 를 내지 않는다.
